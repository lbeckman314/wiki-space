About Wiki Globe

Live edits to Wikipedia articles, placed on a 3D globe as they happen. Edits to astronomy articles appear on a sky map. Inspired by Hatnote's Listen to Wikipedia.

How it works

  1. Listen. The page connects to Wikimedia's public live feed of edits (EventStreams) and keeps edits to articles made by people, not bots, on the Wikipedias you choose (English, the top 20 languages, or all of them).
  2. Locate. For each edited article it looks for a location, in this order:
    • The article's own coordinates on Wikipedia: an exact location.
    • Its Wikidata item's coordinates: also exact.
    • For astronomy articles, a position on the sky map: right ascension and declination for stars and galaxies, today's position calculated from the orbit for asteroids and comets, a computed position for the Sun, Moon and planets, or the centre of its constellation as an approximate fallback.
    • Otherwise a related place on Wikidata: where it is located, its headquarters, where a person was born or died, or its country. These are approximate locations.
    • If none of these exist, the edit goes to the Unplaced list with the reason.
    Requests are batched (up to 50 articles at a time), every answer is cached, and the page backs off when Wikimedia asks it to slow down.
  3. Draw. Edits ripple on the globe and leave a marker that fades over 10 minutes. Edits close together merge into one marker with a count, and split apart as you zoom in.
  4. Replay. Every placed edit is kept in memory while the page is open, so the timeline can rewind and replay them at up to 3600× speed.

Reading the globe

  • Content added.
  • Content removed.
  • A new article.
  • Solid markers are exact locations; faint ones are approximate (a related place).
  • 3A number means several edits close together. Click it to see them all.

Controls

  • Sidebar, Sky map, Timeline buttons under the title show or hide each panel. Your choice is remembered in this browser.
  • Click the placed, exact, approximate or in the sky numbers to list those edits in the sidebar.
  • Search finds edits recorded this session by title, place, language or editor. Combine it with the filters and the Placed and Unplaced tabs.
  • Points switches between numbered markers, bars (additions on the left in teal, removals on the right in orange-red) and a thin heatmap. In heatmap mode, click the globe to open the newest edit near that spot.
  • Follow turns each globe to the newest edit. Pause rotation buttons stop each globe spinning.
  • On the timeline, drag the track or use ← → (1 minute), Shift + arrows (10 minutes), Home (start) and End (live).

How we built it

  1. Feasibility. Confirmed that the live edit feed and the article-coordinates API both work straight from a browser, so no server is needed.
  2. First prototype. A globe.gl page with the live feed, batched coordinate lookups, ripples, a detail card and optional sound.
  3. Wikidata fallback. Used related places on Wikidata so many more edits could be placed, drawn as approximate.
  4. Sky map. Added a second globe for the sky, with star and constellation data, orbit calculations and planet positions.
  5. Polish. Clickable floating titles, a Follow mode, a starfield behind the Earth that matches the sky map, and retries when rate-limited.
  6. Readability. Merged nearby edits into counted markers, added the Unplaced list and per-globe rotation buttons.
  7. Timeline. Recorded edits by the time they were made and added a replay bar with speeds and keyboard control.
  8. Navigation. Show/hide toggles, search, clickable stats and this page.

Run it locally

Wiki Globe is a static site with no build step and nothing to install. You need a browser and any local web server.

  1. Download or clone the project folder.
  2. Start a web server in that folder. With Python 3: 
    cd wiki-globe
python3 -m http.server 8000
    Or with Node.js: 
    npx serve .
  3. Open http://localhost:8000. With npx serve, use the address it prints.

Use a local server rather than opening index.html as a file, so the browser treats the page like a normal website.

Trying things without waiting

Edits to astronomy articles are rare. To simulate edits to chosen articles (this only reads from Wikipedia and Wikidata), open:

http://localhost:8000/?simulate=Andromeda Galaxy|Betelgeuse|Mars

To fill the timeline with 30 minutes of simulated history, run this in the browser console:

for (let i = 0; i < 60; i++) __wikiGlobe.simulate('Edit ' + i, 'en', { lat: 48.86, lng: 2.35 + i * 0.3, time: Date.now() - (60 - i) * 30e3 })

If lookups stall

When Wikimedia rate-limits location lookups, the status line says so and the page waits before retrying. This mostly happens on shared networks such as cloud machines. New edits keep arriving and are placed once lookups resume.

Deploy it

Any static host works, because the site is plain files:

  • GitHub Pages: push the folder to a repository, then in the repository's Settings → Pages, deploy from the main branch, root folder.
  • Netlify or Cloudflare Pages: drag the folder onto their deploy page, or connect the repository with no build command.
  • Your own server: copy the files into any directory your web server already serves.

Each visitor's browser talks to Wikimedia directly, so a busy site multiplies requests to Wikimedia. For many viewers, or for a timeline longer than one browser session, the next step is a small always-on server that reads the feed once, looks up locations once, and shares the results with every visitor.
